# PriceStockMonitor V8.25

本版针对 V8.24 诊断中 XPS 长时间扫描阻塞 Dell Pro 报价的问题修改。

- 先更新各商品的普通报价及当前定制，再安排配置检查。仍共用一个采集窗口，正在等待时显示真实排队状态。
- 默认“快速代表配置”：每轮最多切换 6 次核心选项，配置检查工作预算 60 秒，分轮轮换起点。页面加载、普通报价与恢复另计，不保证整个商品检查在 60 秒内结束。
- 接受配置联动弹窗后，重新核对实际 CPU、显卡、内存、硬盘、屏幕、报价和库存。按实际完整配置去重；不计算选项的笛卡尔积，不把旧状态当成切换成功。
- 代表配置明确标记“未穷举”。它可能漏掉尚未检查组合的折扣；需要全面检查时，在商品编辑页选择“完整遍历（较慢）”。轮换不保证穷举所有组合。
- 保留 V8.24 的读取组件缓存、未确认内存分支处理、逐步显示结果和库存绑定检查。

V8.24 日志确实核对了 64 个不同的核心配置；不能据此认定都是重复。问题是每轮遍历耗时太长，并占用了其他商品需要的窗口。

## 安装

在旧版点击“退出程序”，解压 Windows ZIP 并运行 PriceStockMonitor_Win64_V8.25.exe。原设置和历史沿用。旧商品默认采用快速代表配置，可在编辑页更改。

## 本地测试结果

- Go 全量回归：333 通过、1 跳过、0 失败；跳过的是需要额外原始捕获页面的测试。
- 实际 Chromium 集成运行生产 Go 配置遍历、DOM 操作及可信鼠标点击：6 次配置选择、6 次弹窗确认、4 次其他配置联动，得到 7 个核对后的实际配置。网页为本地构造的 Dell 页面模型。
- 调度回归：慢速 XPS 配置阶段开始前，Dell Pro 最新报价已提交。
- 相关并发 race 检查、Linux/Windows go vet、Windows amd64 GUI 交叉构建通过。
- 实际 Linux 应用与 Chromium 界面：商品增删改、快速/完整模式切换保存、诊断导出、退出重启恢复均通过。三组 Node 页面模型检查通过。
