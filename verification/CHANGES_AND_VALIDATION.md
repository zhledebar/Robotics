# V8.24 修复验证版

本版在 V8.23 源码基础上修改。旧版原始附件和解压源码保持不变。

## 修复

1. 将 Windows 读取组件编译结果在本次运行内缓存。DLL 只有在本进程记录且内容哈希未改变时复用；否则重新编译。新增每次读取耗时日志。
2. 配置确认未实际点击时，移除多余 Windows 快照；配置操作或实际确认后仍重新读取。
3. 硬盘/屏幕优先遍历当前选项，减少往返切换。
4. 内存切换若旧状态连续稳定至少10秒、至少3次读取仍不变化，停止该分支的额外等待，按未确认继续其他分支。没有缩短首次商品内容45秒加载预算。
5. 扫描中逐步展示已核对配置；历史和提醒在整轮结束后提交。取消、删除、编辑隔离旧结果；最终比较仍使用扫描开始前的记录和可信状态。
6. 当响应式购买栏隐藏时，读取同一当前Offer的唯一未禁用购买按钮状态。确认当前总价、选项、无加载/限制/缺货状态；没有购买点击。报价恢复后也只使用独立核对的当前库存，不借用旧原价生成折扣。
7. 诊断导出增加逐条定制结果、隐藏原因和读取耗时，便于追踪实机仍存在的问题。

## 本地验证

- 重新执行 Go 全量回归，具体结果见 verification_v824.json 与 go-tests-v824.jsonl。
- Linux及Windows amd64 go vet；Windows x64 GUI交叉构建。
- 针对缓存、增量结果、取消/编辑/删除、最终提醒基线的新增回归；新增共享状态相关测试使用race detector。
- 三组原有Node页面/确认/展示模型回归。
- 真实Chromium、本地捕获DOM加模拟网站事件处理器：40组合、63次可信鼠标点击；布局隐藏购买栏的库存绑定、禁用/错误Offer拒绝。它不是Dell真实网页扫描。
- 对照相同基础40组合：原V8.23模型需要39次屏幕切换，V8.24只需20次。没有减少覆盖的组合。该结果不是Windows实际扫描速度倍数。
- 实际Linux应用进程与Chromium界面：启动、商品增删改、诊断导出、退出重启与保存恢复。

## 当前尚不能验证

云机器是Linux，无法执行Windows UIAutomation、Windows PowerShell组件、后台独立桌面及Chrome/Edge实机采集。真实Dell网络请求被云代理拒绝。因此编译缓存的Windows实际执行、内存点击失败的实机根因及完整扫描总耗时还没有验证。

这是本地回归通过的修复验证版，不能声明已经证明Windows真实网站全部可用。

## Windows验证步骤

在V8.23点击“退出程序”，再运行同目录提供的PriceStockMonitor_Win64_V8.24.exe。确认界面版本8.24。原配置与历史沿用，观察一轮XPS16扫描，下载诊断。

检查：是否出现本轮有货配置；内存选项是否实际选中；是否仍超时；结果是否在扫描中逐步出现。新增日志会记录读取耗时和内存卡住的分支，新增诊断会记录库存与隐藏原因。若异常仍在，应继续依据该轮诊断定位，而不是扩大超时或宣布修复完成。
